## 2026-05-08 - Optimize potCheck distance calculation for better loop performance
**Learning:** In high-frequency game loops (like checking ball collisions or pocketing), calculating exact Euclidean distance using `Math.sqrt` unconditionally and simultaneously for multiple targets creates unnecessary CPU overhead and garbage collection pressure if intermediate objects are allocated. Furthermore, evaluating all conditions without short-circuiting wastes cycles once a match is found.
**Action:** When implementing spatial checks in loop operations, prefer short-circuiting loops or early returns, use squared distance (`dx*dx + dy*dy <= radius*radius`), and cache repeated coordinate sets as `private static final` arrays at the class level instead of inline logic. Note that logic is often duplicated across `client/Ball.java`, `jfx/Ball1.java`, and `tcpobject/Ball.java` and changes should be mirrored.
