## 2024-05-24 - Avoid exact Euclidean distance in high-frequency game loops
**Learning:** The codebase heavily relies on exact Euclidean distance (`Math.sqrt`) in its physics calculations like `potCheck`. Because these methods are called frequently inside the main UI / game loop, the cost of computing the square root multiple times per frame adds significant overhead, creating a bottleneck. Additionally, repeated getter calls like `getCenterX()` inside these calculation blocks further slow down execution.
**Action:** Replace `Math.sqrt` calculations with squared distance comparisons (`dx*dx + dy*dy <= r*r`) whenever exact distance is not strictly required. Cache repeated coordinate lookups into local variables. Remember to propagate changes across all duplicated `Ball` variants (`src/client/Ball.java`, `src/jfx/Ball1.java`, and `src/tcpobject/Ball.java`) while preserving their specific class structures.
