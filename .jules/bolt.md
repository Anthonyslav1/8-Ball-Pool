## 2024-09-24 - High-Frequency Distance Calculation Optimization
**Learning:** In high-frequency game loops like `potCheck()` for collision or pocket detection, using `Math.sqrt` to calculate exact Euclidean distance unconditionally is a major performance bottleneck due to the cost of floating-point square root operations. Additionally, repeatedly invoking getter methods (`getCenterX()`, `getCenterY()`) within these loops adds unnecessary method call overhead.
**Action:** Always prefer calculating squared distances (e.g., `(dx*dx) + (dy*dy) <= r*r`) over exact distances and apply short-circuiting logic (e.g., `return` early once a pocket collision is found). Also, explicitly cache repeated method call results (like coordinates) in local variables before executing loop or formula logic.
