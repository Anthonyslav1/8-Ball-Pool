
## 2024-05-24 - Avoid Math.sqrt and Object Re-fetching in Game Loops
**Learning:** In the Java multiplayer pool game codebase, the `potCheck()` method across multiple `Ball.java` variants runs frequently during the game loop. It originally performed multiple `Math.sqrt` calculations unconditionally and repeatedly fetched `getCenterX()` and `getCenterY()`, leading to measurable performance overhead (approx. 11-12% penalty in tight loops) and unneeded garbage/CPU cycles.
**Action:** Always prefer squared distance comparisons (`dx*dx + dy*dy <= radius*radius`) over exact Euclidean distance (`Math.sqrt`) when checking proximity or collisions. Furthermore, cache the results of repeated method calls (like coordinate getters) into local variables instead of calling them repeatedly in the same block. Always mirror these optimizations across duplicated class variants (e.g., `client/Ball`, `jfx/Ball1`, `tcpobject/Ball`) while taking care to preserve their unique class-specific state logic.
