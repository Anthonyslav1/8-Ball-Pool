## 2024-05-19 - Avoid Math.sqrt for Distance Calculations in High-Frequency Game Loops
**Learning:** In Java/JavaFX games with custom physics and collision detection, calculating exact Euclidean distance using `Math.sqrt` inside `potCheck()` or collision methods adds significant unnecessary overhead because square roots are computationally expensive. Additionally, calling object getter methods like `getCenterX()` and `getCenterY()` repeatedly in loop logic without caching them multiplies this overhead.
**Action:** Always prefer squared distance comparisons (`dx*dx + dy*dy <= radius*radius`) over calculating exact lengths for simple threshold checks (like pocket detection) in high-frequency game loops. Furthermore, always cache repeated method calls (like `getCenterX()`/`getCenterY()`) into local variables at the beginning of the evaluation block to minimize method call overhead.
