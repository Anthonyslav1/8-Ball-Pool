## 2024-05-24 - Math.sqrt Performance Anti-Pattern in Game Loops
**Learning:** The codebase previously contained unconditional exact Euclidean distance calculations (`Math.sqrt`) inside high-frequency game loop collision and pocket detection methods (`potCheck`) which were heavily duplicated across `src/client/Ball.java`, `src/jfx/Ball1.java`, and `src/tcpobject/Ball.java`. This introduces unnecessary computational overhead.
**Action:** Always prefer short-circuiting logic and mathematically equivalent squared distance comparisons (e.g., `dx*dx + dy*dy <= radius*radius`) over calculating exact Euclidean distances in high-frequency paths. Furthermore, duplicate logic updates must be meticulously synchronized across all structural variants in the codebase while taking care to preserve class-specific variable references (e.g., `Try` vs `Try2`).
