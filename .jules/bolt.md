
## 2024-05-18 - Replacing Unconditional Euclidean Distance Calculations with Squared Distance Comparisons
**Learning:** The codebase repeatedly calculated exact Euclidean distance (`Math.sqrt`) unconditionally in high-frequency game loop methods like `potCheck()` across multiple duplicated classes (e.g., `src/client/Ball.java`, `src/jfx/Ball1.java`, and `src/tcpobject/Ball.java`). This creates unnecessary execution overhead and GC pressure from repeated `Math.sqrt` calculations and redundant coordinate method calls.
**Action:** When calculating distances for bounds checking or collision detection that only need a binary true/false result (like checking if a distance is <= 9), calculate the square of the maximum distance and compare it directly to `(dx*dx + dy*dy)`, skipping the `Math.sqrt()` call. Additionally, cache coordinates `this.getCenterX()` and `this.getCenterY()` into local variables to prevent redundant method calls. Short-circuit logic (`||`) is highly effective here since `potCheck` tests multiple pockets. Ensure updates are replicated across all redundant legacy files (`client`, `jfx`, `tcpobject`).
