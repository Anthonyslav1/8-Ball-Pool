## 2024-05-30 - Game Loop Squared Distance Optimization\n**Learning:** Unconditional `Math.sqrt` checks in `potCheck` were an anti-pattern. Comparing squared distance is logically identical and avoids expensive square root calculations, a major bottleneck during tight execution game loops. The same logic was redundantly duplicated across `client/Ball`, `jfx/Ball1`, and `tcpobject/Ball`, meaning optimizations must be applied carefully to all three while preserving return behavior.\n**Action:** For all future Euclidean distance math inside the game loops (such as collision detection or pocket checks), use squared distance bounds instead of invoking `Math.sqrt`.
