## 2024-03-24 - Avoid unconditional Math.sqrt in high-frequency game loops
**Learning:** Found a performance anti-pattern where exact Euclidean distance (`Math.sqrt`) was being calculated unconditionally for all pockets in the `potCheck` method, which is called on every frame for every ball in the game loop. Also, duplicate coordinate calculation logic existed across multiple `Ball` class variations.
**Action:** Replace `Math.sqrt` with squared distance comparisons (`dx*dx + dy*dy <= radius*radius`), cache pocket coordinates as `private static final` arrays to avoid recalculation, and use short-circuiting (`break` inside a loop) to skip remaining distance checks as soon as a collision is found. Apply these changes consistently across all duplicated variants (e.g., `src/client/Ball.java`, `src/tcpobject/Ball.java`, `src/jfx/Ball1.java`).
