## 2024-05-24 - Unnecessary Math.sqrt in High-Frequency Game Loops
**Learning:** Calculating exact Euclidean distance (`Math.sqrt`) unconditionally in high-frequency game loops (like `potCheck`) is a major performance anti-pattern. Squared distance comparisons (`dx*dx + dy*dy <= radius*radius`) achieve the same boolean result for collision/pocket detection with roughly ~11-12% better performance by avoiding the expensive square root operation. Furthermore, repeated calls to getter methods like `getCenterX()` and `getCenterY()` inside these calculation loops add unnecessary overhead.
**Action:** Always prefer squared distance comparisons over `Math.sqrt` for simple distance threshold checks, and cache frequently accessed properties in local variables within loops or repetitive calculations.
