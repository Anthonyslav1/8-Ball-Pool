## 2024-05-18 - Math.sqrt anti-pattern in game loops
**Learning:** Calculating exact Euclidean distance (`Math.sqrt`) unconditionally in high-frequency game loops (e.g., `potCheck`) is a major performance bottleneck. Since we only need to know if the distance is less than or equal to a radius (9), comparing the squared distance (`dx*dx + dy*dy`) to the squared radius (`9*9 = 81`) yields the exact same result without the expensive square root operation. Furthermore, checking pockets unconditionally (calculating all 6 distances before checking if any is <= 9) wastes computation since the ball can only fall into one pocket at a time.
**Action:** Always prefer short-circuiting logic and squared distance comparisons (`dx*dx + dy*dy <= radius*radius`) for collision and pocket detection. Also, avoid redundant method calls by caching values like `getCenterX()` into local variables within the loop.
